# Puzzles Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rated Lichess puzzles, a daily puzzle on Home and "Learn from your mistakes" puzzles from reviewed games.

**Architecture:** A build script turns the Lichess CSV into static rating-band shards in `public/puzzle-data/`. Pure modules
(`puzzles.ts`, `mistakes.ts`, `puzzleStore.ts`) hold the logic; `puzzleData.ts` fetches; `pages/Puzzles.tsx` renders
with the existing Board and `play-layout` styles.

**Tech Stack:** React 19, chess.js, Chessground (Board), Vitest, Node script with `zstd` for the data build.

**Spec:** `docs/superpowers/specs/2026-10-18-puzzles-design.md`

## Global Constraints

- No backend; same-origin static files only (COEP require-corp stays).
- Storage key `rookahead.puzzles.v1`; every read/write in try/catch like `games.ts`.
- Rating starts 1500; K = 60 for the first 10 puzzles, 32 up to 50, then 16.
- Mistake classes: `mistake`, `miss`, `blunder`; alternative accepted when expected-point loss < `LOSS_BANDS.good` (0.05).
- Shard line: `id fen_with_underscores m1,m2,… rating theme1,theme2`; 500 per shard, 8 000 per band.
- Daily: day n = whole UTC days since 2026-01-01; line `n mod 1000` of `daily.txt`.
- Copy and code style match the existing pages (short comments, no semicolons, 2-space indent).

## Review Focus

- A puzzle whose final move has several mates: any mating move is accepted (solver test `accepts another mate on the last move`).
- Promotion moves in solutions (`e7e8q`): Board's picker sends `promotion`; solver compares full UCI (test `promotion must match`).
- Leaving mid-puzzle after a wrong move: still failed on return, no second rating drop (store test `failed puzzle is only counted once`).
- Reviews of games where the board faced Black: mistakes are Black's moves (mistakes test `uses the orientation side`).
- Shard fetch fails / offline: error card with Retry, no crash (manual check on preview with network offline).

### Task 2: `src/lib/puzzles.ts` (pure logic)

**Produces:**
- `interface Puzzle { id: string; fen: string; moves: string[]; rating: number; themes: string[] }`
- `parsePuzzleLine(line: string): Puzzle | null`
- `type SolveState = { status: 'playing' | 'solved' | 'failed-playing'; played: string[] }` — `played` = moves on the board after the start FEN (includes `moves[0]`).
- `startSolve(p): SolveState` (played = [moves[0]]); `tryMove(p, s, uci): { state: SolveState; result: 'correct' | 'solved' | 'wrong'; reply?: string }` (correct move → appends it and the reply; wrong → state unchanged except status `failed-playing`); `solution(p, s): string[]` (remaining moves).
- `playerColor(p): Color`; `newRating(rating, puzzleRating, won, played): number` (rounded); `pickBand(rating, bands: number[], rand): number`; `dailyIndex(date: Date, length: number): number`; `THEME_LABELS: Record<string, string>` + `themeLabel(t)`.

- [ ] Tests `src/lib/puzzles.test.ts`: parse round trip and `null` on junk; correct sequence solves; wrong move → `wrong` + failed status; `accepts another mate on the last move`; `promotion must match`; K schedule (`newRating(1500,1500,true,0) === 1530`, played 10 → 1516, played 50 → 1508); pickBand clamps to nearest existing band; dailyIndex(2026-01-01) = 0, (2026-01-02) = 1, wraps at length.
- [ ] Implement, tests pass, commit.
